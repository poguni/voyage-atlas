## 1. 개요

### 1.1 배경
여행은 다녀온 뒤에 기억이 흩어지기 쉽습니다. 사진은 휴대폰에 쌓이고, 언제 어디를 몇 번 갔는지는 금방 헷갈립니다. 반대로 "언젠가 가고 싶은 곳"은 머릿속에만 머물다 잊힙니다.

종이 **스크래치 맵**은 다녀온 나라의 금박을 긁어 색을 드러내는 단순한 행위만으로 큰 성취감을 줍니다. 이 앱은 그 감각을 디지털로 옮기고, 종이 지도로는 할 수 없는 다음 세 가지를 더합니다.

1. **기록**: 방문 날짜와 횟수, 함께 간 사람, 메모를 쌓아 "나의 여행 연대기"를 만듭니다.
2. **통계와 성취**: 방문 국가 수, 대륙별 비율, 여행 일수 합계, 배지와 마일스톤으로 성장을 눈으로 확인합니다.
3. **희망**: 위시리스트와 AI 추천 여행지를 지도 위에 별처럼 띄워 "다음 여정"을 꿈꾸게 합니다.

### 1.2 제품 목표
- 국가·시도를 클릭 몇 번으로 색칠하고, 방문 횟수와 날짜를 남긴다.
- 지도를 열 때마다 **성취감**(얼마나 다녔는지)과 **설렘**(어디로 갈지)을 함께 느끼게 한다.
- 결과를 SNS에 자랑하고 싶을 만큼 아름다운 **공유 이미지**로 만든다.
- 세 AI 모델(Claude Sonnet 5.5, GPT-6 Luna, Gemini 3.8 Flash)이 내 여행 이력을 바탕으로 다음 여행지를 추천하고, 지도에 핀으로 보여 준다.

### 1.3 감성 목표 (디자인이 전달해야 할 감정)
| 감정 | 앱에서 느끼는 순간 | 구현 수단 |
|---|---|---|
| **성취감** | 나라를 클릭하면 금박이 긁히며 색이 번질 때, 마일스톤을 달성할 때 | 스크래치 애니메이션, 금빛 파티클, 배지 획득 연출, 진행률 링 |
| **추억** | 여행 기록을 다시 볼 때 | 연대기 타임라인, 여행 경로 다시 보기(비행 궤적 애니메이션) |
| **기대와 희망** | 위시리스트·AI 추천을 볼 때 | 반짝이는 별 핀, D-day 카운트다운, "꿈 → 현실" 전환 연출 |
| **자부심** | 공유 이미지를 만들 때 | 포스터 품질의 내보내기 템플릿 |

### 1.4 범위에서 제외하는 것 (Non-goals)
- 로그인, 회원가입, 서버 백엔드, 클라우드 동기화(기기 간 이동은 JSON 백업으로 처리)
- 친구와의 실시간 지도 공유, 소셜 피드, 랭킹
- 일정 짜기, 항공권·숙소 예약(트립픽과 5-1 "여행 일정 플래너"에서 다룸)
- GPS 기반 자동 방문 감지
- 사진 원본 보관(P2에서 썸네일만 기기 안에 저장)

## 2. 사용자와 사용 시나리오

### 2.1 주 사용자
- **본인(개발자 겸 유일한 사용자)**: 사진 촬영과 여행을 좋아하고, 가족·친구·혼자 여행을 모두 다닙니다. 통계 전공자라 숫자로 정리된 기록에서 재미를 느낍니다.
- **간접 사용자**: 공유 이미지를 받아 보는 가족·친구, SNS 팔로워.

### 2.2 대표 시나리오

**시나리오 A: 처음 시작하기 (지난 여행 한꺼번에 입력)**
1. 앱을 열면 어두운 밤하늘 위에 금박으로 덮인 세계 지도가 천천히 떠오릅니다.
2. "빠른 색칠" 모드를 켜고 일본, 베트남, 프랑스, 이탈리아를 연달아 클릭합니다. 누를 때마다 금박이 긁히며 색이 퍼지고, 상단의 "방문 국가 4 / 195" 숫자가 올라갑니다.
3. 4개국을 넘기자 "첫 번째 대륙을 넘어섰어요: 유럽" 배지가 나타납니다.
4. 대한민국 탭으로 바꿔 제주, 부산, 강원을 색칠합니다.

**시나리오 B: 여행 하나를 자세히 기록하기**
1. "여행 추가"를 눌러 "2025 가을 교토·오사카"를 만들고 날짜(10/3~10/8), 동행(가족), 별점, 메모를 입력합니다.
2. 방문 도시로 교토와 오사카를 검색해 추가합니다. 일본의 방문 횟수가 3회로 올라가고 색이 한 단계 진해집니다.
3. 통계 화면에서 올해 여행 일수가 자동으로 합산됩니다(겹치는 날짜는 한 번만 셉니다).

**시나리오 C: 다음 여행 꿈꾸기**
1. AI 추천 탭에서 "내년 2월, 5박 6일, 가족, 사진 촬영 좋아함, 안 가 본 나라"를 고릅니다.
2. 실행 전 모델별 예상 비용을 확인하고 실행합니다.
3. 지도 위에 세 모델의 추천지가 색깔별 핀으로 나타나고, 세 모델이 모두 추천한 곳은 금빛 별로 반짝입니다.
4. 마음에 드는 "조지아 트빌리시"를 위시리스트에 담고 목표 시기를 "2027년 5월"로 정합니다.

**시나리오 D: 자랑하기**
1. 연말에 공유 스튜디오에서 "올해의 여정" 템플릿을 고릅니다.
2. 인스타그램 세로(1080×1350) 크기로 미리 보고, 날짜는 숨긴 채 PNG로 저장하거나 휴대폰 공유 시트로 바로 보냅니다.

## 3. 핵심 개념과 용어

| 용어 | 정의 |
|---|---|
| **장소(Place)** | 지도에서 색칠할 수 있는 단위. 국가, 한국 시도, 한국 시군구(P1), 도시(핀) |
| **여행(Trip)** | 날짜 범위가 있는 한 번의 여정. 여러 장소를 포함 |
| **방문(Visit)** | 특정 장소를 어떤 여행에서 방문한 기록. 방문 횟수 = 그 장소가 포함된 여행 수. 여행 기록 없이 "방문함" 단순 표시만 있으면 1회. 여행 기록이 생기면 단순 표시는 그 기록에 흡수됨(예: 단순 표시 + 여행 2개 = 2회) |
| **상태(Status)** | 장소별 상태: `방문함` / `경유` / `위시리스트` / `미방문` |
| **빠른 색칠** | 여행을 만들지 않고 "방문함"만 표시하는 모드. 날짜는 나중에 채울 수 있음 |
| **마일스톤·배지** | 일정 조건(예: 10개국, 6대륙)을 달성하면 얻는 성취 표시 |

> **설계 원칙**: 정확한 기록(여행 단위)과 빠른 입력(장소 단위 색칠)을 모두 지원합니다. 처음에는 빠르게 색칠하고, 시간이 날 때 날짜와 메모를 채우는 흐름을 기본으로 합니다.

## 4. 전체 화면 흐름

```
             ┌──────────────────────── 지도 홈 (메인) ────────────────────────┐
             │  [세계]  [대한민국]  [지구본]      검색      통계 요약 HUD      │
             │  클릭 → 장소 팝오버(방문함 / 위시 / 기록 추가)                  │
             └───┬──────────┬───────────┬────────────┬────────────┬───────────┘
                 │          │           │            │            │
          [여행 연대기] [위시리스트]  [AI 추천]   [통계·배지]  [공유 스튜디오]
           여행 추가·편집  목표 시기    조건 입력    대시보드     템플릿·크기
           경로 다시 보기  D-day       비용 확인    마일스톤     PNG·공유
                                      3모델 핀
                                                   [설정] API 키, 모델, 홈 공항, 백업
```

- 지도는 항상 배경에 살아 있고, 다른 화면은 지도 위에 떠 있는 **유리 패널(사이드 패널·하단 시트)**로 엽니다. 화면을 옮겨도 지도가 사라지지 않아 "내 세계" 안에 머무는 느낌을 줍니다.
- AI를 호출하는 곳(AI 추천)에서는 실행 전에 **모델별 예상 비용 확인 창**이 먼저 뜹니다(트립픽과 같은 방식).

## 5. 기능 요구사항

우선순위는 **P0**(MVP 필수), **P1**(v1 포함), **P2**(이후 확장)로 표시합니다.

### F1. 지도 보기와 조작 (P0)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F1-1 | **세계 지도**: 국가 단위 경계(TopoJSON). 기본 투영법은 Natural Earth(또는 Equal Earth) | P0 |
| F1-2 | **대한민국 지도**: 17칸 시도 경계(16개 광역 행정구역 중 전남광주통합특별시를 광주권·전남권으로 나눔, 8.4절). 독도·울릉도·제주 포함 | P0 |
| F1-3 | 확대·축소·이동(마우스 휠, 드래그, 핀치 줌), "전체 보기" 버튼 | P0 |
| F1-4 | 마우스를 올리면 국가명(한국어·영어), 국기, 상태, 방문 횟수 툴팁 | P0 |
| F1-5 | 크기가 작아 클릭하기 어려운 나라(싱가포르, 몰디브, 바티칸 등)는 **원형 마커**로 함께 표시 | P0 |
| F1-6 | **장소 검색**: 국가·시도·도시를 한국어/영어로 검색해 지도 이동 후 팝오버 열기. 한국어 초성 검색(예: "ㅍㄹㅅ" → 프랑스) | P0 / 초성 P1 |
| F1-7 | **지구본 모드**: 정사영(Orthographic) 투영으로 둥근 지구를 드래그해 회전. 방문 국가가 빛나고 느리게 자전 | P1 |
| F1-8 | 세계 ↔ 지구본 ↔ 한국 전환 시 부드러운 투영 전환 애니메이션 | P1 |
| F1-9 | **한국 시군구 지도**: 시도를 두 번 클릭하면 시군구 단위로 확대해 색칠 | P1 |
| F1-10 | **도시 핀**: 방문 도시를 지도 위 점으로 표시. 확대 수준에 따라 이름 표시 | P1 |
| F1-11 | 지도 색칠 기준 전환: 상태별 / 방문 횟수별(진하기) / 마지막 방문 연도별 / 동행 유형별 | P1 |
| F1-12 | 3D 시네마틱 지구본(WebGL, 대기 광채·비행 궤적) | P2 |

### F2. 방문 표시와 기록 (P0)
| ID | 요구사항 | 우선순위 |
|---|---|---|
| F2-1 | 장소를 클릭하면 **팝오버**: [방문함] [위시리스트] [기록 추가] [상세 보기] | P0 |
| F2-2 | **빠른 색칠 모드**: 켜면 클릭 한 번으로 바로 "방문함" 토글(팝오버 생략). 연속 입력에 최적화 | P0 |
| F2-3 | 상태 선택: 방문함 / 경유(공항만) / 위시리스트. 경유는 통계 포함 여부를 설정에서 선택(기본 제외) | P0 |
| F2-4 | **방문 기록 추가**: 방문 날짜(시작~종료, 연·월만 입력도 허용), 동행 유형(혼자/가족/친구/연인/출장), 메모, 별점(1~5) | P0 |

## 6. 디자인 방향

### 6.1 콘셉트: Midnight Atlas & Gold Foil
**밤하늘 위의 금박 스크래치 지도.**

- 기본 화면은 깊은 남색 밤하늘입니다. 아직 가지 않은 땅은 은은한 **금박(골드 포일)**으로 덮여 있어 "긁어 보고 싶은" 느낌을 줍니다.
- 다녀온 곳은 금박이 긁혀 나가며 **오로라 그라데이션**(청록 → 보라 → 분홍)이 드러납니다. 방문 횟수가 많을수록 빛이 진해집니다.
- 위시리스트와 AI 추천은 **별**입니다. 지도 위에서 천천히 반짝이며 "아직 닿지 않은 곳"이라는 희망을 표현합니다.
- 트립픽의 "Night Departure(밤 공항 출발 안내판)" 콘셉트와 같은 밤 세계관을 공유해, 두 앱이 한 가족처럼 보이게 합니다.

**디자인 원칙**
1. **지도가 주인공**: 화면의 70% 이상을 지도에 주고, 나머지 UI는 반투명 유리 패널로 띄웁니다.
2. **클릭마다 보상**: 모든 색칠에 짧고(0.6~0.9초) 기분 좋은 연출을 줍니다. 단, 빠른 색칠 모드에서는 연출을 짧게 줄여 방해하지 않습니다.
3. **숫자는 크게, 자랑스럽게**: 핵심 통계는 큰 세리프 숫자와 카운트업 애니메이션으로 보여 줍니다.
4. **화려함과 가독성의 균형**: 장식 효과는 배경과 강조에만 쓰고, 글자와 버튼은 대비 기준(WCAG AA)을 지킵니다.

- **데스크톱**: 전체 화면 지도 + 왼쪽 상단 통계 HUD(방문국, 대륙, 여행 일수) + 오른쪽 슬라이드 패널(상세·목록) + 하단 중앙 떠 있는 탭 바(지도 / 연대기 / 위시 / AI / 통계 / 공유).
- **모바일**: 지도 전체 화면 + 아래에서 올라오는 시트(3단계 높이: 접힘·절반·전체) + 하단 탭 바. 엄지로 닿는 곳에 주요 버튼 배치.
- 패널은 반투명 유리 효과(`backdrop-filter: blur`)와 얇은 금빛 테두리.

### 6.5 모션과 효과
| 순간 | 연출 | 구현 방법 |
|---|---|---|
| 앱 시작 | 별이 깔린 하늘에서 지도가 떠오르고, 방문국이 순서대로 빛남 | CSS/WAAPI, 1.5초 이내, 두 번째 방문부터는 짧게 |

| 숫자 증가 | 통계 숫자 카운트업, 진행률 링 채워짐 | `requestAnimationFrame` |
| 마일스톤 | 배지가 회전하며 등장, 색종이 | canvas-confetti(금색 팔레트) |
| 위시 별 | 느린 반짝임(3~5초 주기, 별마다 위상 다름) | CSS 애니메이션 |

| 경로 다시 보기 | 대권 궤적이 그려지며 비행기 아이콘 이동 | `d3.geoInterpolate` + `stroke-dashoffset` |

- 효과음(금박 긁는 소리, 배지 획득 차임)은 기본 꺼짐, 설정에서 켭니다(P1).

## 7. 기술 스택

### 7.1 기술 스택 검토: 단일 HTML로 충분한가?
원래 추천안(단일 HTML + SVG 지도)은 기능 구현에는 충분하지만, 이번에 원하는 **화려한 연출, 지구본, 고해상도 공유 이미지, 오프라인 사용**까지 고려하면 아래처럼 조금 확장하는 것이 좋습니다.

| 안 | 구성 | 장점 | 단점 | 판단 |
|---|---|---|---|---|
| A. 원안 | 단일 HTML + SVG(TopoJSON) | 가장 단순, 파일 하나 | 코드가 4,000줄을 넘으면 관리 어려움, 지도 데이터를 CDN에 의존, 지구본·연출 구현 시 파일 비대 | 프로토타입용 |
| **B. 채택** | **빌드 없는 다중 파일 정적 앱**: `index.html` + ES 모듈(`js/*.js`) + 지도 데이터(`data/*.json`) + **D3(지도 엔진)** + PWA | 빌드 도구 없이 GitHub Pages에 바로 배포, 바이브 코딩 시 파일별로 나눠 요청하기 쉬움, 지도 데이터 자체 보관으로 안정적, 오프라인 가능 | 파일이 여러 개(문제 아님) | **채택(v0.2 확정)** |
| C. 고급 | Vite + TypeScript + Svelte/React + MapLibre GL 또는 globe.gl(Three.js) | 최고 수준의 3D·성능, 타입 안정성 | 빌드·설정 부담, 난이도 ★★★★로 상승, 스크래치 연출·공유 이미지 구현이 오히려 복잡 | 과함(3D 지구본만 P2로 부분 도입) |

**결론(v0.2 확정)**: **B안**으로 개발하고, 3D 시네마틱 지구본(F1-12)만 P2에서 globe.gl을 지연 로딩으로 추가합니다. 2D 지도와 2D 지구본은 같은 D3 엔진의 투영법만 바꾸면 되므로 코드 하나로 세 가지 보기를 만들 수 있습니다.

| 형태 | 빌드 없는 정적 웹 앱, ES 모듈 | 로컬 서버나 GitHub Pages에서 바로 실행. 라이브러리는 import map으로 CDN 고정 버전 사용 |

| 오프라인 | PWA(서비스 워커로 앱·지도 데이터 캐시, 홈 화면 추가) | 여행지에서 데이터 없이도 기록 가능 |

- CDN 라이브러리는 **정확한 버전을 고정**합니다(예: `d3@7.9.0`, `topojson-client@3.1.0`). 개발 시작 시 최신 안정 버전을 확인해 정합니다.
- 지도 데이터는 CDN이 아닌 **저장소 안 `data/`에 보관**해 외부 변경이나 장애에 흔들리지 않게 합니다.

## 8. 지도 구현 상세

### 8.1 렌더링 구조
```
<div id="map">
  <canvas id="sky">        별 배경, 반짝임(Canvas)
  <svg id="atlas">
    <defs>                 금박 패턴, 오로라 그라데이션, 노이즈 필터, 스크래치 마스크
    <g class="graticule">  경위선(은은하게)
    <g class="land">       국가/시도 path (data-id = ISO 숫자 코드 / 행정구역 코드)
    <g class="markers">    작은 나라 원형 마커, 도시 핀
    <g class="wish">       위시·AI 추천 별 핀
    <g class="routes">     여행 경로 궤적
  </svg>
  <canvas id="fx">         파티클(색칠·축하 효과)
</div>
```

### 8.2 색칠과 스크래치 효과
1. 각 국가 `path`는 기본으로 금박 패턴(`fill: url(#foil)`)을 가집니다.
2. 방문 처리 시 같은 모양의 **오로라 레이어 path**를 위에 추가하고, 클릭 좌표를 중심으로 한 원 `clipPath`의 반지름을 0에서 국가 경계 상자 대각선 길이까지 0.7초 동안 키웁니다.
3. 원 가장자리에 노이즈 필터(`feTurbulence` + `feDisplacementMap`)를 걸어 긁힌 듯 거친 경계를 만듭니다.
4. 동시에 Canvas 레이어에서 금빛 가루 파티클 20~40개를 흩뿌립니다.
5. 애니메이션이 끝나면 clipPath를 제거하고 단순 채움으로 바꿔 성능을 확보합니다.

### 8.3 작은 나라와 섬
- 화면상 면적이 일정 픽셀 이하인 국가는 중심점에 원형 마커(반지름 4~6px)를 추가하고, 클릭 영역을 넓힙니다.
- 마커 대상은 데이터 로드 시 `d3.geoArea`로 자동 계산합니다.

### 8.4 한국 지도
- **17칸**(서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주)을 기본으로 합니다. 2026년 7월 1일 광주광역시와 전라남도가 **전남광주통합특별시**(코드 12)로 통합되어 행정구역은 16개가 되었지만, 여행 기록에서는 광주와 전남을 구분하는 편이 자연스러워 지도에서는 **광주권(옛 광주광역시 5개 구)**과 **전남권**으로 나눕니다(v0.4 결정). 툴팁·상세에는 행정구역 명칭(전남광주통합특별시)을 함께 표시합니다.
- 독도와 울릉도가 지도 데이터에 포함되어 있는지 반드시 확인하고, 초기 화면에서 보이도록 범위를 잡습니다.
- 시군구 데이터는 용량이 크므로 시도를 확대할 때 지연 로딩합니다(P1).
- 행정구역 코드는 행정안전부 행정표준코드 2자리(서울 11, 부산 26, 대구 27, 인천 28, 대전 30, 울산 31, 세종 36, 경기 41, 충북 43, 충남 44, 경북 47, 경남 48, 제주 50, 강원 51, 전북 52)를 씁니다. 광주권·전남권은 통합 전 코드 **29·46**을 앱 코드로 그대로 씁니다(통합특별시 코드 12는 쓰지 않음). 특별자치도 전환으로 바뀐 코드(강원 42 → 51, 전북 45 → 52)는 **매핑 표**로 처리해 오래된 백업 데이터도 읽을 수 있게 합니다. (시안은 통계청 코드를 썼으나 실제 앱은 이 코드로 통일합니다.)
- 독도는 경상북도(울릉군) 영역의 일부로 그려지며, 크기가 매우 작으므로 **원형 마커와 "독도" 라벨을 항상 함께 표시**해 어느 확대 수준에서도 보이게 합니다. 세계 지도에서도 대한민국을 확대하면 독도 마커가 보이게 합니다.

### 8.5 성능 목표
- 첫 화면(110m 지도)은 1.5초 이내 표시, 50m 지도는 백그라운드에서 교체.
- 확대·이동 중에는 60fps에 가깝게 유지(필요하면 이동 중에는 Canvas로 그리고 멈추면 SVG로 복귀).
- 지구본 회전은 Canvas 렌더링을 기본으로 합니다.

## 9. AI 추천 설계

### 9.1 OpenRouter 기본 사항
- 엔드포인트: `POST https://openrouter.ai/api/v1/chat/completions`(OpenAI 호환 형식)
- 헤더: `Authorization: Bearer <키>`, `Content-Type: application/json`, 선택적으로 `HTTP-Referer`(GitHub Pages 주소), `X-Title`(Voyage Atlas)
- 모델 목록·단가: `GET https://openrouter.ai/api/v1/models`
- 응답의 `usage`로 실제 토큰 수와 비용을 기록합니다.

> **구현 전 확인 필요**: 세 모델의 OpenRouter 슬러그, 구조화 출력(`response_format`) 지원 여부, 웹 검색 방식과 요금은 자주 바뀝니다. 코드에 고정하지 않고 설정값으로 둡니다(트립픽 PRD 5.1절과 같은 원칙).

### 9.2 모델 구성
| 역할 | 기본 모델 | 지도 핀 색 | 기대 성격 |
|---|---|---|---|
| 모델 A | **Claude Sonnet 5.5** | 코랄 | 내 이력과 연결한 섬세한 추천 이유 |
| 모델 B | **GPT-6 Luna** | 민트 | 폭넓은 지식, 의외의 발견 |
| 모델 C | **Gemini 3.8 Flash** | 하늘 | 빠르고 저렴, 재추천·간단 작업에 적합 |

> **2026-10-16 확인**: 슬러그 `anthropic/claude-sonnet-5.5`·`openai/gpt-6-luna`·`google/gemini-3.8-flash`, 세 모델 모두 `response_format`(json_schema) 지원, 응답 `usage.cost`로 실제 비용 확인. 슬러그는 설정에서 바꿀 수 있고 단가는 모델 목록 API로 다시 조회합니다.

### 9.3 프롬프트에 넣는 맥락
- 추천 조건(F7-1)
- 이력 요약(개인 메모·동행인 이름은 **보내지 않음**): 방문 국가 목록과 방문 횟수, 대륙 분포, 별점 4점 이상 여행지, 위시리스트, 최근 3년 여행 패턴(계절·기간·동행 유형)
- 제외 목록: "안 가 본 나라만"이면 방문국 전체, 이전에 "제외"한 추천지

### 9.4 출력 스키마 (JSON)
```json
{
  "recommendations": [
    {
      "name_ko": "트빌리시",
      "name_en": "Tbilisi",
      "country_iso2": "GE",
      "type": "city",
      "lat": 41.7151,
      "lon": 44.8271,
      "reason": "별점 5점을 준 포르투처럼 언덕 위 구시가지와 노을 풍경이 아름답습니다.",
      "linked_history": ["포르투"],
      "best_months": [5, 6, 9, 10],
      "flight_hours_from_origin": 10.5,
      "budget_level": "중",
      "photo_spots": ["나리칼라 요새 노을", "구시가지 발코니 골목"],

      "confidence": "high"
    }
  ]

```

### 9.5 결과 병합과 합의 표시
1. 세 모델 결과를 `country_iso2 + 도시 이름(정규화)`로 묶습니다. 이름이 다르게 나와도 좌표가 50km 이내면 같은 곳으로 봅니다.
2. 추천한 모델 수로 합의 수준을 매깁니다: 3/3 → 금빛 큰 별, 2/3 → 금빛 별, 1/3 → 모델 색 핀.
3. 카드 목록은 합의 수준 → 조건 적합도 순으로 정렬하고, 카드 안에서 모델별 추천 이유를 탭으로 비교합니다.

### 9.6 신뢰성
- 좌표는 `d3.geoContains`로 국가 경계 안에 있는지 확인합니다(F7-8).
- 비행시간·예산은 "대략적인 값"임을 표시합니다.
- 응답 JSON은 스키마 검증 후, 실패하면 오류를 붙여 1회 재요청, 그래도 실패하면 원문을 보여 줍니다.
- 안전·입국 정보는 다루지 않고, 카드에 "출발 전 외교부 해외안전여행 정보를 확인하세요" 링크를 고정으로 둡니다.

### 9.7 비용 표시
- 트립픽과 같은 방식으로 **실행 전 예상 비용 확인 창**(모델별 입력·출력 토큰 추정, USD·원화)과 **실행 후 실제 비용**을 보여 줍니다. 상한은 두지 않습니다.
- 한 번의 추천은 모델당 1회 호출(총 3회)이며, 이력 요약을 압축해 입력 토큰을 줄입니다.
- 같은 조건이면 캐시된 결과를 먼저 보여 주고 "새로 추천"을 눌러야 다시 호출합니다.

- `schemaVersion`으로 향후 구조 변경 시 자동 변환(마이그레이션)합니다.

### 10.3 통계 계산 규칙
| 항목 | 규칙 |
|---|---|
| 방문 국가 수 | 상태가 `visited`인 국가 + 방문 도시가 있는 국가. 경유는 설정에 따름(기본 제외). **대한민국도 방문 국가로 셈**: 한국 시도·도시를 하나라도 방문하면 `country:410`이 자동으로 방문함 처리됨 |
| 방문 횟수 | 그 장소가 포함된 여행 수(**시작일이 오늘 이후인 예정 여행은 제외**). 여행이 0개이고 단순 표시(`visited`)만 있으면 1회. 여행이 1개 이상이면 단순 표시는 흡수되어 여행 수만 셈 |
| 기준 국가 목록 | 기본: UN 회원국 193 + 옵서버 2(바티칸, 팔레스타인) = 195. 대만·홍콩·마카오·그린란드 등은 "지역"으로 따로 세고, 설정에서 "전체 지역 포함" 선택 가능 |
| 대륙 분류 | 6대륙 고정 매핑 표(`tools/country-meta.mjs` → `countries.ko.json`). 러시아·키프로스는 유럽, 튀르키예·조지아·아르메니아·아제르바이잔·카자흐스탄은 아시아, 이집트는 아프리카. 대륙별 국가 수: 아시아 47, 유럽 45, 아프리카 54, 북아메리카 23, 남아메리카 12, 오세아니아 14 |
| 여행 일수 | 여행별 `종료일 − 시작일 + 1`. 전체 합계는 모든 여행 날짜를 **합집합**으로 만든 뒤 일수를 셈(겹치는 출장·여행 중복 방지). 연·월만 있는 여행은 "날짜 미상 일수"로 별도 표시 |
| 해외/국내 | 한국 장소만 포함한 여행은 국내, 그 외는 해외 |
| 이동 거리 | 홈 공항 → 경유지 순서 → 홈 공항의 대권 거리 합(`d3.geoDistance` × 지구 반지름 6,371km) |

### 10.4 공유 이미지 생성 방식
1. 템플릿별로 **오프스크린 SVG**를 구성합니다(지도 + 제목 + 통계 + 장식).
2. 글꼴은 `document.fonts.ready` 이후 사용하고, SVG 안에서 글자 대신 **Canvas `fillText`**로 글자를 그려 한글이 깨지지 않게 합니다. (SVG를 이미지로 바꿀 때 외부 글꼴이 적용되지 않는 문제를 피함)
3. SVG를 Blob → `Image` → `Canvas`(목표 크기 × 2배)에 그린 뒤 `toBlob('image/png')`.
4. 모바일은 `navigator.canShare({ files })`가 참이면 공유 시트, 아니면 다운로드.
5. 금박·오로라 질감은 미리 만든 노이즈 텍스처(PNG, 저장소 보관)를 패턴으로 사용해 출력물에서도 같은 느낌을 냅니다.

- 통계 HUD와 대시보드(방문국, 대륙 비율, 여행 일수 합집합, 시도 정복률, TOP 5)
- 위시리스트(별 핀, 목록, 꿈 → 현실 전환)
- 통계 계산 단위 테스트(겹치는 날짜, 경유 제외, 날짜 미상)
- **완료 기준**: 여행 기록을 넣으면 통계가 정확히 계산되고 위시리스트를 관리할 수 있음

### M3. 공유 이미지
- 공유 스튜디오, 템플릿 ①②, 크기 4종, 테마 3종, 숨기기 옵션, Web Share API
- **완료 기준**: 휴대폰에서 인스타그램 세로 이미지를 만들어 바로 공유 가능

### M4. AI 추천
- 설정(API 키, 모델·단가, 연결 테스트), 예상 비용 확인 창, 실제 비용 기록
- 3모델 병렬 추천, 결과 병합·합의 표시, 지도 핀, 좌표 검증, 위시리스트 담기
- **완료 기준**: 조건을 넣고 세 모델의 추천을 지도에서 비교해 위시리스트에 담을 수 있음

### M5. 성취와 연출 강화 (P1)
- 마일스톤·배지, 지구본 모드, 투영 전환, 경로 다시 보기, 연대기 재생, 한국 시군구, 도시 핀, 템플릿 ③④, PWA, 연도별 차트, 이동 거리

### M6. 확장 (P2)
- 3D 시네마틱 지구본, AI 여행 성향 분석, 사진 썸네일, 위시 보드, 인쇄용 포스터, 트립픽 연동

> **Claude Code 활용 팁**: 마일스톤마다 이 PRD의 해당 절(예: "5장 F2, 8.2절")을 붙여 넣어 요청하면 결과가 안정적입니다. M1은 `map/engine.js`와 데이터 파일 준비부터, M2는 `stats.js` 순수 함수와 테스트부터 만드는 순서를 권합니다.

## 15. 성공 지표 (개인 사용 기준)

- 지금까지 다녀온 모든 국가·시도를 첫날 10분 안에 색칠한다.
- 이후 여행마다 귀국 1주일 안에 여행 기록을 남긴다(기록률 90% 이상).
- 공유 이미지를 1회 이상 SNS나 가족 단톡방에 공유한다.
- 위시리스트 항목 중 1년 안에 1곳 이상을 "꿈 → 현실"로 전환한다.
- AI 추천지 중 1곳 이상을 실제 여행 후보(트립픽)로 검토한다.
